How joblist is built

One engineer directing a tier of coding agents, and reviewing everything they produce. "Built with AI agents" means very little without the control structure around it, so this is the control structure.

The same idea governs the tool and the process that writes it: let the cheap deterministic thing do as much as possible, and spend the expensive model only where judgement is genuinely required. In the tool that is the filter stack running before the scorer. In the process it is the routing below.

The four rules that make it work

Workers return facts, never transcripts

A search agent returns filters.py:114, stage_salary is tri-state and nothing else. File dumps and narration defeat the purpose: the orchestrator's context is the scarce resource being protected.

Decisions come home

A worker that hits a spec gap reports it rather than choosing. Every architectural call here — tri-state salary, hydrating after the funnel, keeping the personal list out of the prompt — was made at the top and handed down as a constraint.

Review is adversarial and has no memory

The reviewing pass runs in a fresh context and did not write the code, so it cannot be persuaded by its own reasoning from an hour earlier.

The gate is mechanical, not conversational

Nothing merges because an agent said it was finished. It merges because the suite and ruff pass in CI. Agents are fast and confidently wrong.

Where it went wrong, which is the useful part

The first version of this tool was itself an agentic loop: a model calling a fetch tool once, a scoring tool per job, then a compile tool. It grew a transcript it resent every turn, so cost scaled quadratically with the number of jobs, and it never completed a single run. That commit is still in the history. The rewrite deleted the loop and kept the model as a ranker.

Three later bugs make the same point about the gate. None was caught by reading the code.

  1. A word boundary read pesos as dollars

    A currency regex using \b missed 25,000PHP and parsed it as dollars, overstating one wage by roughly 58×. The code looked correct. The output did not.

    found by measuring · now a test

  2. One board was scored on a teaser

    An entire source was being judged on a 280-character truncated snippet rather than the full advert, because its listing feed only carries a preview. Hydration now runs after the funnel, for survivors only.

    found by measuring · now a test

  3. "The model returned nothing" was a budget bug

    Three cover letters came back empty and were read as the model declining to write them. It was not declining. Extended thinking was on by default and spent the entire 1,200-token output budget inside a thinking block, leaving no text at all. One look at stop_reason settled in seconds what re-reading the prompt had not; with thinking disabled the same advert answered in 74 tokens.

    found by measuring · now a named error

The lesson generalises to the routing above. An agent is worth reaching for when the task needs judgement on unstructured input, and is the wrong tool when the task is a for loop with an API bill attached. The same sentence describes why the tool puts its filters before its model.

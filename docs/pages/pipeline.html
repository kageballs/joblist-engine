Three decisions that are the whole design

The model sits at the bottom

Not the top. Field comparisons remove 93.4% before anything is billed, so the expensive stage only ever reads the remainder. Version one did the opposite and never completed a single run.

Hydrate after the funnel

Fetching each advert's own page at fetch time would spend a request on every listing the salary floor discards for free. 89 pages were fetched instead of 2,690.

Blockers never touch the API

The model reports what a posting asks for. Matching that against what you cannot supply happens locally — so the list never leaves the machine, and editing it re-prices the entire stored history with zero API calls.

Reproducible, and not

Every stage falls into one of two categories, and almost every other choice follows from keeping them apart.

DeterministicNon-deterministic
Stages sources/*, filters.py, blockers.py, digest.py, report.py scorer.py, cover.py
Costzeroone batched call per run, plus letters
Re-runningfree, and safecosts money, and the answer changes
Needs a keynoyes

No temperature, top_p or seed is pinned anywhere, so the two model stages run at provider defaults. That is not theoretical: one board listed a single advert under two ids, and the identical input returned a reasoned decline once and an empty response the other time. Anything downstream of a model call treats a malformed or empty response as expected, not exceptional.

Boards are isolated

A score is only meaningful inside the board that produced it. Himalayas averages 20.3 and OnlineJobs 5.9, so a single ranked list across both silently hands every cover-letter slot to the generous board — and starves the board where clearing the bar was the harder achievement. Slots are handed out round-robin, each board's best in turn. Every threshold, floor and age window is declared per board; a new board with no entry in the profile fails the run rather than inheriting someone else's tuning.

What never leaves the machine

Three things are deliberately withheld from the hosted dashboard, and each for a different reason.

Rejects

Their reasons name flagged employers, so publishing them would make that list inferable from a dashboard anyone could be shown.

Advert text

Bulk employer copy, kept out of the pushed column allowlist.

Cover letters

Written from the resume, in the candidate's own voice. The push refuses any target host that is not localhost — enforced in code, with tests for the substring traps a naive check waves through.
